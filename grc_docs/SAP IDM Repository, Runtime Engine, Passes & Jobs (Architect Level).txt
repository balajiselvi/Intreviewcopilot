

SAP IDENTITY MANAGEMENT (SAP IDM) 
Chapter 2 – SAP IDM Repository, Runtime Engine, Passes & Jobs (Architect Level) 
 
Q157. Explain the SAP IDM Repository. 
Interviewer's Objective 
The interviewer wants to know whether you understand how SAP IDM stores and 
manages identity data. 
 
Executive Answer 
The SAP IDM Repository is the central database that stores all identity-related 
information required for identity lifecycle management. 
It contains: 
• Identity records  
• Privileges  
• Roles  
• Tasks  
• Workflow information  
• Provisioning status  
• Audit logs  
• Repository configuration  
The Runtime Engine continuously reads and updates the repository during 
provisioning and synchronization. 
The repository acts as the single source of truth for SAP IDM operations. 
 
Q158. Explain the Identity Store Schema. 
Executive Answer 
The Identity Store schema is the logical structure used to organize identity data. 
Major object types include: 
• MX_PERSON  

• MX_ROLE  
• MX_PRIVILEGE  
• MX_GROUP  
• MX_ASSIGNMENT  
• MX_TASK  
• MX_EVENT  
These objects are linked through relationships, allowing SAP IDM to determine who 
should receive which access.

Q159. What are Passes in SAP IDM? 
One of the most frequently asked technical questions. 
 

Executive Answer 
A Pass is a sequence of provisioning tasks executed by the Runtime Engine. 
Each pass performs one logical operation. 
Examples include: 
• Create User  
• Modify User  
• Assign Role  
• Remove Role  
• Synchronize Password  
• Disable Account  
Passes ensure provisioning activities are executed in a controlled and repeatable 
sequence. 
 
Example 
HR Event 
 
↓ 
 
Create Identity Pass 
 
↓ 
 
Assign Role Pass 
 
↓ 
 
Provision SAP User Pass 
 
↓ 
 
Provision AD User Pass 
 
↓ 
 
Notification Pass 

 
Q160. What is a Job in SAP IDM? 
Executive Answer 
A Job is a collection of one or more Passes executed by the Runtime Engine. 
Jobs automate identity lifecycle activities. 
Examples: 
• Initial Load Job  
• HR Synchronization Job  
• Password Synchronization Job  
• De-provisioning Job  
• Active Directory Synchronization Job  
A Job may contain multiple Passes executed in a predefined sequence.

Q162. Explain Event Handling in SAP IDM. 
 
Executive Answer 
SAP IDM is event-driven. 
An event initiates processing within the Runtime Engine. 
Examples: 
• New employee  
• Employee transfer  
• Termination  
• Password reset  
• Manager change  
• Department change  
Each event triggers the appropriate Job and Pass sequence automatically.

Q164. Explain Dispatcher in SAP IDM. 
Architect-level interview question. 
 
Executive Answer 

The Dispatcher manages communication between the Runtime Engine and 
connected target systems. 
Responsibilities include: 
• Scheduling provisioning requests  
• Queue management  
• Load balancing  
• Error handling  
• Retry mechanisms  
• Communication management  
Without the Dispatcher, provisioning tasks cannot be efficiently distributed across 
systems. 
 
Q165. Explain JavaScript in SAP IDM. 
Very common because many implementations use custom scripting. 
 
Executive Answer 
JavaScript is used within SAP IDM to implement custom business logic that cannot 
be achieved through standard configuration. 
Typical use cases include: 
• Attribute transformations  
• Conditional provisioning  
• Data validation  
• Custom workflow logic  
• Dynamic role assignment  
• Repository updates  
• String manipulation  
• Integration logic  
 
Interview Tip 

Mention that JavaScript should be modular, well-documented, and used only 
where standard functionality is insufficient to simplify long-term maintenance.

One of the most valuable production support questions. 

 
Executive Answer 
I follow a structured approach: 
Step 1

Step 2 
Review Runtime Engine logs. 
 
Step 3 
Verify Job execution. 
 
Step 4 
Review Pass execution. 
 
Step 5 
Validate JavaScript tasks. 
 
Step 6 
Check SQL query results. 
 
Step 7 
Review Dispatcher queues.

Validate target system response.

Q170. Real Production Scenario 
Interviewer 
"A new employee has been created in HR, but no SAP account is created. How 
would you troubleshoot?" 
 
Executive Answer 
My approach would be: 
1. Confirm the employee exists in the authoritative HR system.  
2. Verify the HR synchronization job completed successfully.  
3. Check that the identity was created in the SAP IDM repository.  
4. Review Runtime Engine logs for processing errors.  
5. Verify the correct Job and Pass sequence executed.  
6. Review any JavaScript or SQL tasks involved in identity creation.  
7. Validate connector communication with the SAP target system.  
8. Check provisioning logs and error messages returned by the connector.  
9. Correct the identified issue and rerun provisioning if appropriate.  

10. Confirm that the SAP account is created successfully and document the root 
cause.  
 
Q171. Real Technical Scenario 
Interviewer 
"A JavaScript task that assigns business roles is suddenly failing after a transport. 
How would you investigate?" 
 
Executive Answer 
I would approach the issue methodically: 
1. Review the Runtime Engine logs to identify the failing task and error details.  
2. Compare the transported JavaScript with the previous working version to 
identify changes.  
3. Verify that all required repository attributes and constants exist in the target 
environment.  
4. Check whether dependent SQL queries or repository objects return the 
expected data.  
5. Validate that the transport included all related configuration objects, not 
just the script.  
6. Test the logic in a non-production environment using representative data.  
7. Correct the issue, perform regression testing, and only then transport the fix 
to production.  
This minimizes risk while ensuring the integrity of the provisioning process.
