# Real Interview Feedback Log

Phase 1 is closed. This is the primary input for what comes next — real usage, not more
synthetic benchmarking. Add one entry per question that's worth remembering, right after a real
(or real-practice) interview session, while it's fresh.

Entries in `eval/results/` answer "does the system behave the way we designed it to." This file
answers a different question: "does it actually help." Log a question here when the answer
reveals something the benchmarks wouldn't catch — a real judgment call, not a repeat of an
already-known limitation (Engineering Memory arbitration, missing acquisition UI, no principle
mining — those are already tracked in `docs/EXPERIENCE_ACQUISITION_ENGINE_DESIGN.md`).
