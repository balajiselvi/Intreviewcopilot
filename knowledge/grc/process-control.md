# SAP GRC Process Control

## Access Control and Process Control

SAP Access Control and SAP Process Control are related GRC applications with different jobs. Access Control analyzes access risk, routes access requests, manages business roles, controls emergency access, and certifies authorizations. Process Control documents the internal-control environment, tests and assesses controls, tracks issues through remediation, and certifies and reports the state of those controls. In GRC 12.0 the applications can share organization data. A Process Control control can be used as an Access Control mitigation control, and a Process Control process can be used as an Access Control business process. Process Control can use Access Risk Analysis to monitor segregation-of-duties violations. Sharing master data does not make one product the implementation of the other. Source checked 2026-10-21: SAP Process Control 12.0.27 application guide, Integration with Access Control, https://help.sap.com/doc/d83af7d22baa49829e464111338e9c12/12.0.27/en-US/loio60d658f576b6452eb0f943c04b354018_en.pdf and the SAP Access Control 12.0 SP31 introduction.

## Why a concise CV may omit Process Control

A two-page CV summarizes the core SAP Security and GRC responsibilities and does not enumerate every related capability. Process Control is part of that GRC scope even when the CV names Access Control and does not give Process Control a separate bullet. A Process Control control is the object used as an Access Control mitigation control. A Process Control process is the object used as an Access Control business process. Do not call a process a mitigation control. Answer the control-documentation, testing, remediation, and reporting method from the verified product procedure. Do not invent a client, date, team size, or metric, and do not open by saying the experience is absent.

## Process Control master data

Create Process Control master data in the order recommended by the 12.0.27 application guide: regulation group, regulation, and regulation requirement, then organizations, the risk catalog, control objectives, account groups, and business processes with subprocesses and controls. Assign corporate and organization roles, regulations to subprocesses and controls, subprocesses to organizations, and local subprocess and local control roles after those objects exist. Indirect entity-level controls can be created later and assigned to an existing organization. A master-data change can require approval when the Activate Workflow for Master Data Changes customizing activity is enabled for that entity. Source checked 2026-10-21: SAP Process Control 12.0.27, Master Data Flow.

## Implement Process Control

Use the basic role SAP_GRC_FN_BASE for users who run Process Control, SAP_GRC_FN_BUSINESS_USER for work on assigned entities, SAP_GRC_FN_ALL for administrative customizing such as organization definition, and SAP_GRC_FN_DISPLAY for display-only review. Assign SAP_GRC_FN_ALL through PFCG when a power user must delegate that administrative authorization. Document the organization, process, subprocess, and control before scheduling a test. Configure the source-system connector and the control data the test depends on before the Planner creates work. Validate the setup by opening an assigned control and confirming the owner, tester, and regulation assignment are present. Source checked 2026-10-21: SAP Process Control 12.0.27, Standard Roles and Master Data Flow.

## Test and remediate a Process Control

Create and assign the manual control test plan, then trigger the workflow in the Planner with a start date and a due date. Perform the test from Assessments, Manual Test Plans, while the status is Ready or Reserved. Record Pass or Fail for the test activities. If the test fails, create an issue and assign an issue owner. The issue owner assigns a remediation plan with a start date and a due date, or closes the issue when no plan is required. The remediation owner performs the plan and completes it. The issue owner reviews the result and closes the issue. The system then routes the retest to the original tester, and every issue and remediation plan must be closed before that retest is sent. A passed test does not permit an issue. Source checked 2026-10-21: SAP Process Control 12.0.27, Performing Manual Tests of Effectiveness and Remediating Evaluation Issues.

## Troubleshooting: unexpected automated or manual control test result

An unexpected Process Control test result is a control-evaluation defect until evidence shows otherwise. Identify the control, organization, regulation, tester, and Planner assignment first. Confirm the control definition, local control ownership, and the data or connector the automated evaluation depends on before changing Access Control MSMP or PFCG roles. For a manual test, reopen Assessments, Manual Test Plans and verify the plan status was Ready or Reserved, the due date window is current, and Pass or Fail was recorded against the intended activities. For an automated evaluation, validate the source-system connector and the control data used by that evaluation, then rerun after correcting master data or connector evidence. If the test fails correctly, create or continue the issue and remediation plan rather than forcing a Pass. Do not diagnose a Process Control test with AGR_USERS, AGR_1251, or BW analysis authorizations unless the control itself monitors those access objects. Source checked 2026-10-21: SAP Process Control 12.0.27, Performing Manual Tests of Effectiveness and Remediating Evaluation Issues; Master Data Flow; Standard Roles.

## Move a Process Control change through development quality and production

Record the Process Control configuration change on a transport request in the development system. Release that request only after the control, owner, and test-plan setup has been checked in development. Import the request into quality with the Transport Management System and repeat the control test there. Treat a successful import return code as technical delivery, not as user-acceptance approval. Obtain the business sign-off for the control test in the quality or designated acceptance client before production is authorized. Import the same released request into production in the approved window and confirm the control, workflow, and owner assignment after import. A failed quality test or a missing dependency stops the production import until the correction is transported and retested. Source checked 2026-10-21: the control and test sequence is from SAP Process Control 12.0.27. The transport path is the ABAP Change and Transport System used by the GRC ABAP add-on.
