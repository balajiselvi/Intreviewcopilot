Everything You Should Know About PFCG in SAP – The Brain of Role-Based Access Control 

 

🌈 If you're working with SAP Security, PFCG (Profile Generator) isn’t just a transaction code - it’s where security meets functionality. Whether it’s S/4HANA or ECC, understanding PFCG can transform how securely and efficiently your users operate. 🌈  

 

🌈 Why Do We Use PFCG? 

PFCG is used to create, manage, and assign roles - each defining what users can or cannot do in the SAP system. Without structured roles, access becomes chaotic and non-compliant. 

 

⏩ Ensures access is aligned with job responsibilities 

⏩ Supports compliance (SOX, GDPR) by enforcing SoD rules 

⏩ Makes auditing access easier 

⏩ Provides reusable and scalable role templates 

 

🌈 Types of Roles in PFCG 

 

😊 Single Role 

⏩ Contains authorizations, transactions, reports, and menus. 

⏩ Used for specific job functions (e.g., “AP Invoice Processor”). 

 

😊 Composite Role 

⏩ Groups multiple single roles under one umbrella. 

⏩ Helps assign multiple accesses at once, commonly used for cross-functional roles. 

 

😊 Derived Role 

⏩ Inherits from a master role but differs in organizational levels like Company Code or Plant. 

⏩ Useful for multi-location orgs. 

 

🌈 Colors in Authorization Maintenance: 

Colors guide the completeness and accuracy of your role’s authorizations: 

🟢 Green – Everything is maintained and correct. 

🟡 Yellow – Values are missing or partially maintained. 

🔴 Red – Object entries are mandatory but missing. 

 

🤩 Tip: Only generate profiles when you see all green! 

 

🌈 How SU01/SU10/SE93 Work with PFCG 

 

⏩ SU01: Assigns roles to individual users that are created in PFCG. 

⏩ SU10: Mass assigns/removes roles in bulk. 

⏩ SE93: Custom transaction codes you add in roles. 

⏩ SUIM: Monitor role assignments and authorization checks. 

⏩ SU53/STAUTHTRACE: Identify failed authorization checks linked to PFCG roles. 

 

🌈 What Happens Behind the Scenes in PFCG? 

 

⏩ Menu tab: Determines the transactions and reports visible to users. 

⏩ Authorization tab: Generates authorization objects based on the menu or manually in Expert mode. 

⏩ User tab: Assigns generated profiles to selected users. 

⏩ When you generate the role, a profile (with name like Z_SALES_READ_ONLY) is created and stored in table USR12. 

 

🌈 Common Real-World Use Cases 

 

⏩ S/4HANA greenfield project - building new role designs 

⏩ Internal audit SoD failures - revising composite roles 

⏩ Fiori Launchpad apps not loading - troubleshooting catalog/target mapping 

⏩ ECC to S/4HANA migration - using derived roles per Company Code 

⏩ GDPR compliance - removing sensitive authorizations like S_USER*
