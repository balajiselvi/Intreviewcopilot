

SAP IDENTITY MANAGEMENT (SAP IDM) 
Chapter 1 – SAP IDM Architecture & Identity Lifecycle 
 
Q146. What is SAP Identity Management (SAP IDM)? 
Interviewer's Objective 
The interviewer wants to determine whether you understand SAP IDM as an 
enterprise Identity Governance and Administration (IGA) platform rather than 
simply a user provisioning tool. 
 
Executive Answer 
SAP Identity Management (SAP IDM) is an enterprise Identity Governance and 
Administration solution that automates the complete identity lifecycle across SAP 
and non-SAP systems. 
It centralizes identity creation, modification, provisioning, synchronization, and de-
provisioning based on business rules and organizational events. 
SAP IDM supports: 
• Joiner, Mover, Leaver (JML) processes  
• Identity lifecycle automation  
• User provisioning  
• Role assignment  
• Workflow-driven approvals  
• Integration with HR systems  
• Active Directory and LDAP integration  
• SAP GRC integration  
• Audit and compliance reporting  
Its objective is to ensure that users receive the right access at the right time while 
reducing manual administration and improving governance. 
 
Business Benefits 
SAP IDM provides: 

• Automated provisioning  
• Centralized identity repository  
• Reduced onboarding time  
• Consistent access across systems  
• Lower administrative effort  
• Improved audit readiness  
• Stronger security controls

Q148. What is the Identity Center? 
 
Executive Answer 
The Identity Center is the administrative interface used to configure and manage 
SAP IDM. 
Administrators use it to: 
• Create repositories  
• Configure provisioning  
• Manage identity attributes  
• Build workflows  
• Configure jobs and passes  
• Monitor provisioning  
• Maintain connectors  
• Configure business roles  
Think of it as the primary administration console for SAP IDM. 
 
Q149. What is the Identity Store? 
 
Executive Answer 
The Identity Store is the central repository where SAP IDM maintains identity 
information. 

It stores: 
• User identities  
• Roles  
• Privileges  
• Organizational data  
• Business attributes  
• Workflow information  
• Provisioning status  
• System references  
The Identity Store becomes the authoritative source for identity data within SAP 
IDM. 
 
Q150. What is the Runtime Engine? 
This is one of the most frequently asked SAP IDM questions. 
 
Executive Answer 
The Runtime Engine is the processing engine responsible for executing provisioning 
tasks and workflows. 
It performs: 
• Identity synchronization  
• Provisioning  
• De-provisioning  
• Job execution  
• Pass execution  
• Workflow processing  
• Event handling  
Without the Runtime Engine, SAP IDM cannot automate provisioning activities.

Employee joins the company.

↓ 
Assigns roles. 
↓ 
Creates Active Directory account. 
↓ 
Creates SAP user. 
↓ 
Sends notification. 
 
Q151. Explain Joiner, Mover and Leaver (JML). 
One of the most common interview questions. 
 
Executive Answer 
JML is the core identity lifecycle process. 
Joiner 
A new employee joins the organization. 
Typical actions: 
• Create identity  
• Provision SAP account  
• Create Active Directory account  
• Assign business roles  

• Send welcome notification  
 
Mover 
An employee changes role, department, or location. 
Typical actions: 
• Remove obsolete access  
• Assign new business roles  
• Update organizational attributes  
• Synchronize target systems  
 
Leaver 
An employee leaves the organization. 
Typical actions: 
• Disable accounts  
• Remove roles  
• Lock SAP users  
• Disable AD account  
• Archive identity  
• Revoke privileged access  
 
Interview Tip 
Always emphasize that timely de-provisioning is just as important as onboarding. 
 
Q152. Explain the Provisioning Framework. 
 
Executive Answer 
The Provisioning Framework enables SAP IDM to communicate with target systems. 
It handles: 

• User creation  
• User updates  
• Role assignment  
• Password synchronization  
• Account deletion  
Target systems may include: 
• SAP ECC  
• S/4HANA  
• Active Directory  
• LDAP  
• Azure AD  
• Databases  
• Cloud applications  
 
Q153. How does SAP IDM integrate with Active Directory? 
 
Executive Answer 
SAP IDM integrates with Microsoft Active Directory using LDAP or supported 
connectors. 
Common provisioning activities include: 
• Create AD user  
• Update user attributes  
• Assign groups  
• Disable accounts  
• Password synchronization  
This enables centralized identity management across SAP and Windows 
environments.

Q155. Explain Identity Governance. 
 
Executive Answer 
Identity Governance ensures that user identities and access rights are managed 
according to organizational policies throughout their lifecycle. 
Key governance principles include: 
• Least Privilege  
• Role-Based Access Control (RBAC)  
• Segregation of Duties (SoD)  
• Periodic Access Reviews  
• Workflow Approvals  
• Auditability  
• Access Certification  
SAP IDM provides automation, while SAP GRC enforces governance policies. 
 
Q156. Real Interview Scenario 
Interviewer 
"An employee transfers from Finance to Procurement. How would SAP IDM handle 
this?" 
 
Executive Answer 
The process would follow the Mover lifecycle. 
1. Detect the organizational change from the authoritative HR source.  
2. Update identity attributes in the Identity Store.  
3. Remove Finance-specific business roles.  
4. Assign Procurement business roles based on the new position.  
5. Synchronize changes with connected systems such as SAP S/4HANA, Active 
Directory, and other applications.  

6. If required, trigger SAP GRC approval or risk analysis before provisioning.  
7. Record the change for audit purposes.  
This ensures access remains aligned with the employee's current responsibilities 
while reducing the risk of excessive privileges. 
 
Architect's Insight 
One of the strongest statements you can make in an interview is: 
"SAP IDM is an identity administration platform, whereas SAP GRC is an access 
governance platform. Together they provide a complete Identity Governance and 
Administration (IGA) solution." 
That distinction demonstrates architectural understanding rather than product 
knowledge alone.
