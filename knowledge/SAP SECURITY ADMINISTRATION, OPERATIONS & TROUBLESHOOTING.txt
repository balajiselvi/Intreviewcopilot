Chapter 1 – User Administration, Authorization Troubleshooting & Daily Operations 
 
Q185. Explain the User Administration process in SAP. 
Interviewer's Objective 
The interviewer wants to understand whether you know the complete user lifecycle 
rather than just creating users in SU01. 
 
Executive Answer 
User Administration is the process of creating, maintaining, monitoring, modifying, 
and removing SAP user accounts throughout their lifecycle. 
It includes: 
• User creation  
• User modification  
• Role assignment  
• Password administration  
• User lock/unlock  
• User deletion (where applicable)  
• License management  
• User validity management  
• Periodic access review  
User Administration should always follow approved governance processes and 
integrate with SAP GRC or Identity Management solutions where available.

Q186. Explain SU01. 
One of the most common SAP Security interview questions. 
 
Executive Answer 
SU01 is the primary transaction used to maintain SAP user master records. 

It is used for: 
• Create users  
• Change users  
• Display users  
• Lock/Unlock users  
• Password reset  
• Role assignment  
• Profile assignment  
• User parameters  
• License assignment  
• Validity dates

Q190. Explain User Buffer. 
Frequently asked in troubleshooting interviews. 
 
Executive Answer 
The User Buffer temporarily stores user authorization data in memory. 
Benefits: 
• Faster authorization checks  
• Reduced database access  
• Improved performance  
After role changes: 
User Comparison 
↓ 
Buffer Refresh 
↓ 
New authorization becomes active. 

 
Interview Tip 
Many authorization issues occur because the user buffer has not yet been 
refreshed after role changes. 
 
Q191. What is User Comparison? 
 
Executive Answer 
User Comparison synchronizes role assignments with the generated authorization 
profiles assigned to users. 
Whenever a role changes: 
Role 
↓ 
Generate 
↓ 
User Comparison 
↓ 
User Buffer 
↓ 
Authorization Active 
Without user comparison, the user may not receive updated authorizations 
immediately. 
 
Q192. Explain SU53. 
Probably the most common troubleshooting question. 
 
Executive Answer 
SU53 displays the last failed authorization check performed by the current user. 
It helps identify: 

• Missing authorization objects  
• Missing field values  
• Missing activities  
• Missing organizational values  
 
Best Practice 
The user should execute SU53 immediately after encountering the authorization 
error because it only retains the most recent failed check. 
 
Limitations 
SU53 only shows: 
• The current user's last failed authorization check.  
It does not show: 
• Successful checks.  
• Historical authorization failures.  
• Other users' authorization checks.  
 
Q193. Explain STAUTHTRACE. 
Senior-level interview favorite. 
 
Executive Answer 
STAUTHTRACE provides a detailed trace of both successful and failed authorization 
checks. 
Unlike SU53, it allows administrators to: 
• Trace any selected user.  
• View successful and failed checks.  
• Analyze authorization objects.  
• Review authorization field values.  
• Investigate complex authorization issues.

Q195. Explain ST01. 
 
Executive Answer 
ST01 is the SAP System Trace transaction. 
It traces: 
• Authorization checks  
• RFC calls  
• Kernel activity  
• SQL statements  
• Lock operations  

It provides deeper analysis than SU53 and is often used for complex authorization 
or technical investigations. 
 
Q196. When would you use SU53, STAUTHTRACE and ST01? 
 
Executive Answer 
SU53 
For quick analysis immediately after a user encounters an authorization error. 
 
STAUTHTRACE 
When investigating complex authorization issues, missing authorization values, or 
problems affecting another user. 
 
ST01 
When a deeper technical trace is required, such as analyzing authorization 
behavior together with RFC calls or SQL activity. 
 
Q197. Production Issue 
Interviewer 
"A user reports that yesterday they could execute ME21N successfully. Today they 
receive an authorization error after a transport. How would you troubleshoot?" 
 
Executive Answer 
My troubleshooting approach would be: 
1. Confirm the exact error message and transaction.  
2. Ask the user to execute SU53 immediately after reproducing the issue.  
3. Run STAUTHTRACE if additional analysis is required.  
4. Compare the user's current roles with the previous transport or recent role 
changes.  

5. Verify whether SU24 proposals or authorization objects were modified.  
6. Check whether organizational values such as Company Code, Plant, or 
Purchasing Organization have changed.  
7. Confirm that User Comparison has been executed and the user buffer has 
been refreshed.  
8. Validate the transport contents to identify any security-related changes.  
9. Test the corrected authorization in QA before implementing the fix in 
Production.  
This structured approach minimizes unnecessary role changes and focuses on 
identifying the true root cause. 
 
Q198. Real Manufacturing Scenario 
Interviewer 
"A Production Planner can create production orders but cannot release them. The 
role has not changed. What would you investigate?" 
 
Executive Answer 
I would investigate systematically: 
1. Reproduce the issue and capture the exact error.  
2. Review SU53 or STAUTHTRACE for missing authorization objects.  
3. Check whether the required authorization includes the correct activity value 
for releasing production orders.  
4. Validate organizational values such as Plant and Production Scheduler.  
5. Confirm whether a recent transport changed SU24 proposals or 
authorization defaults.  
6. Compare the affected user's role with a user who can successfully release 
production orders.  
7. Verify with the PP functional consultant whether business process changes 
introduced new authorization requirements.  
This avoids assuming the issue is purely security-related and ensures both 
functional and security perspectives are considered.

Q200. Executive Interview Question 
Interviewer 
"What is the biggest mistake SAP Security administrators make?" 
 
Executive Answer 
One of the biggest mistakes is treating authorization issues as requests to grant 
more access instead of understanding the underlying business requirement. 
My approach is always: 

1. Understand the business process.  
2. Identify the root cause using SU53, STAUTHTRACE, or ST01.  
3. Validate whether the requested access is appropriate.  
4. Apply the Principle of Least Privilege.  
5. Consider governance implications, including SoD and audit requirements.  
6. Document and test the solution before moving it to production.  
This ensures that security supports the business without introducing unnecessary 
risk.
